# Lambda Shutdown Pattern Analysis - Deployment & Validation Guide

## Prerequisites

- AWS CLI configured with appropriate credentials
- AWS SAM CLI installed
- Node.js 22+ installed
- Bash available (Git Bash on Windows, or native on Mac/Linux)
- Amazon Bedrock access enabled in your Region for the Claude inference profile you set as `BedrockModelId` (see Step 3)

> **Windows shortcut:** `deploy.ps1` performs Steps 1-4 (build the layer with the
> correct executable bit, install dependencies, `sam build`, and `sam deploy`) in a
> single command. See `TEST_RUNBOOK.md`. The manual steps below work on any platform.

## Step 1: Build the Extension Layer

**Windows (CMD):**
```cmd
cd extension\nodejs-example-telemetry-api-extension
npm install
cd ..\..
powershell -ExecutionPolicy Bypass -File build-layer.ps1
```

**Mac/Linux:**
```bash
cd extension/nodejs-example-telemetry-api-extension
npm install
cd ../..
bash build-layer.sh
```

## Step 2: Build the Recommendation Engine Dependencies

```bash
cd insights/recommendation-engine
npm install
cd ../..

cd insights/cold-start-correlation
npm install
cd ../..
```

## Step 3: Build and Deploy

```bash
sam build -t template-prebuilt.yaml
sam deploy --guided
```

When prompted:
- **Stack name:** `shutdown-pattern-analysis`
- **Region:** `us-east-1` (or your preferred region with Bedrock access)
- **BedrockModelId:** `us.anthropic.claude-sonnet-4-6` (or another **active** Claude inference profile ID you have enabled in your Region — see the note below)
- **Confirm changes before deploy:** Y
- **Allow SAM CLI IAM role creation:** Y
- **SampleFunction may not have authorization defined - Is this okay?** Y
- **Save arguments to samconfig.toml:** Y

## Step 4: Note the Stack Outputs

After deployment, note these values from the output:

```bash
aws cloudformation describe-stacks --stack-name shutdown-pattern-analysis \
  --query "Stacks[0].Outputs" --output table
```

You need:
- `ApiEndpoint` — for the load test
- `RecommendationPipelineArn` — for triggering the AI recommendation engine
- `DashboardUrl` — Overview dashboard (analysis + AI recommendations)
- `DeepDiveDashboardUrl` — Deep dive metrics and sizing tables

## Step 5: Run the Full Pipeline (Load Test + Analysis)

> **Windows users:** Open a **Git Bash** terminal (included with Git for Windows) and navigate to your local repo root directory. The test script requires bash, curl, and xargs which are all included with Git Bash.

This runs the load test, waits for shutdowns, and triggers the AI recommendation engine automatically:

```bash
bash test/hello.sh <ApiEndpoint> <Region> <RecommendationPipelineArn>
```

**Without recommendation pipeline** (load test only, ~10 min):
```bash
bash test/hello.sh <ApiEndpoint> <Region>
```

**With recommendation pipeline** (full run, ~30 min):
```bash
bash test/hello.sh <ApiEndpoint> <Region> <RecommendationPipelineArn>
```

Replace `<ApiEndpoint>`, `<Region>`, and `<RecommendationPipelineArn>` with the values from your stack outputs (Step 5).

**Total runtime: ~30 minutes**
- Phase 1 (1 min): High traffic — spins up multiple Lambda environments
- Phase 2 (6 min): Reduced traffic — some environments go idle
- Phase 3 (3 min): High traffic — triggers cold starts after shutdowns
- Phase 4 (15 min): No traffic — waits for all environments to shut down
- Phase 5: Triggers Step Functions pipeline → extracts metrics → generates AI recommendations → updates dashboard

## Step 6: View the Dashboards

Open the `DashboardUrl` from the stack outputs for the overview. Set the time range to cover the last 1-2 hours.

**Overview Dashboard** (`Lambda-Shutdown-Pattern-Analysis`):
1. **Interpretation Guide** — how to read each widget
2. **AI Recommendations** — generated by Bedrock with specific actions and implementation guidance
3. **Analysis Table** — shutdown metrics grouped by speed (Fast/Medium/Slow)
4. **Number Widgets** — key metrics at a glance
5. **Summary Charts** — Shutdown speed pie, Idle gap distribution, Traffic drop correlation

**Deep Dive Dashboard** (`Lambda-Shutdown-Deep-Dive`):
1. **Time Series** — Shutdown lapse trend, Cold start rate, Invocation rate, Memory, Duration
2. **Distributions** — Detailed idle gap breakdown and trend
3. **Sizing Tables** — Cold start cost impact, Provisioned concurrency data, Keep-alive interval estimation

Both dashboards have navigation links to each other at the top.

## Running for a Custom Time Range

To regenerate recommendations for a different time window (e.g., production traffic from yesterday):

```bash
# Convert your desired time range to epoch seconds
# Example: last 6 hours
START=$(date -d '6 hours ago' +%s)  # Linux
# START=$(date -v-6H +%s)           # Mac
END=$(date +%s)

aws stepfunctions start-execution \
  --state-machine-arn <RecommendationPipelineArn> \
  --input "{\"startTime\": $START, \"endTime\": $END}"
```

## Troubleshooting

**Dashboard widgets show "No data":**
- Ensure the time range covers when the load test ran
- Check that the log group `/metrics/lambda-execution-lifecycle` has log streams with data

**Step Function fails at GenerateRecommendations:**
- Verify Bedrock model access is enabled in your Region for the `BedrockModelId` you used.
- **Legacy model error** (`ResourceNotFoundException: ... marked by provider as Legacy`):
  Bedrock models are retired over time. List the active Claude models and inference
  profiles in your Region, then redeploy (or update the function's `BEDROCK_MODEL_ID`
  environment variable) with a current one:
  ```bash
  aws bedrock list-foundation-models --region <Region> --by-provider anthropic \
    --query "modelSummaries[?modelLifecycle.status=='ACTIVE'].modelId" --output text
  aws bedrock list-inference-profiles --region <Region> \
    --query "inferenceProfileSummaries[?contains(inferenceProfileId,'claude')].inferenceProfileId" --output text
  ```
  Update without a full redeploy:
  ```bash
  aws lambda update-function-configuration \
    --function-name shutdown-pattern-generate-recommendations --region <Region> \
    --environment "Variables={BEDROCK_MODEL_ID=<active-inference-profile-id>}"
  ```

**Load test script errors:**
- Ensure `curl` and `aws` CLI are available in your bash environment
- Verify the API endpoint returns `{"message":"hello world"}` with a manual curl

**Extension not writing metrics:**
- Check the function's default log group for errors: `aws logs filter-log-events --log-group-name /aws/lambda/shutdown-pattern-sample-function --filter-pattern "Error" --limit 5`
- Verify the dedicated log group has streams: `aws logs describe-log-streams --log-group-name /metrics/lambda-execution-lifecycle --limit 3`
